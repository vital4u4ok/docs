## Deprecation

Marked at every level the specification allows:

- **Operations** — `DELETE /accounts/{accountId}` and `GET /fx/rates`, both returning
  `Deprecation` and `Sunset` headers.
- **Parameters** — the offset `page` parameter, superseded by `cursor`.
- **Schema properties** — `Account.legacyCode`, present only on accounts migrated before 2019.
- **Security schemes** — `apiKeyQuery` and `oauth2Implicit`. This level is new in OpenAPI 3.2.

## Parameter serialization

Every style, in every location that allows it, with both `explode` values.
`GET /diagnostics/echo` and `GET /diagnostics/path/...` carry the combinations the
banking operations do not already use, and each parameter there ships a worked example
showing the data form beside the serialized form.

| Style | Location | `explode` | Serializes as |
| --- | --- | --- | --- |
| `form` | query | `false` | `filters=open,frozen` |
| `form` | query | `true` | `tags=retail&tags=eu` |
| `form` | query, object | `false` | `flat=status,open,currency,GBP` |
| `spaceDelimited` | query | `false` | `bbox=-0.51%2051.28` |
| `spaceDelimited` | query | `true` | `bboxExploded=-0.51&bboxExploded=51.28` |
| `pipeDelimited` | query | `false` | `codes=GB%7CIE` |
| `pipeDelimited` | query | `true` | `codesExploded=GB&codesExploded=IE` |
| `deepObject` | query | `true` | `where[status]=open` |
| `simple` | header, array | `false` | `hal,problem-json` |
| `simple` | header, object | `true` | `sampled=true,rate=0.1` |
| `simple` | path, object | `true` | `kind=card,id=42` |
| `form` | cookie, object | `true` | `theme=dark; density=compact` |
| `form` | cookie, array | `false` | `session_flags=beta,internal` |
| `label` | path, string | default | `.EU-LON-01` |
| `label` | path, array | `true` | `.eu.lon.01` |
| `matrix` | path, object | `true` | `;lat=51.5;long=-0.12` |
| `matrix` | path, array | `false` | `;matrixArray=1,2,3` |

Where a style is omitted the default applies, which is `simple` in a path or header and
`form` in a query or cookie, both with `explode: false`.

Three fields beyond style and explode also appear:

- `allowReserved: true` on `q`, so reserved characters pass through unencoded.
- `allowEmptyValue: true` on `verbose`, so the key may appear with no value.
- `content` instead of `schema` on `selector`, which carries a JSON object in one
  parameter, and on the whole query string of `GET /reports/balances` through the 3.2
  `in: querystring` location.

## Security

Every scheme type the specification defines, and every OAuth 2 flow.

| Type | Schemes |
| --- | --- |
| `oauth2` | `oauth2AuthCode`, `oauth2ClientCredentials`, `oauth2Implicit`, `oauth2Password`, `oauth2Device`, `oauth2AllFlows` |
| `http` | `basicAuth`, `bearerJwt`, `digestAuth`, `httpSignature` |
| `apiKey` | `apiKeyHeader`, `apiKeyQuery`, `apiKeyCookie` |
| `mutualTLS` | `mutualTls` |
| `openIdConnect` | `openId` |

All five flows appear: `authorizationCode`, `clientCredentials`, `implicit`, `password` and
the 3.2 `deviceAuthorization`. `oauth2AllFlows` declares all five in a single scheme, which
the Flows Object allows and most descriptions never do.

Requirements are combined every way the specification permits: a global default, a
per-operation override, two schemes ANDed inside one requirement, several requirements ORed,
and `security: []` to opt out entirely.

## Request and response bodies

- `application/json`, `application/hal+json` and `application/problem+json`
- `application/merge-patch+json` and `application/json-patch+json` on the same operation
- `multipart/form-data`, `multipart/mixed` and `multipart/related`, each with per-part
  `encoding` and part headers
- `application/jsonl` and `text/event-stream` for streamed responses, `application/x-ndjson`
  for a streamed request body
- `application/pdf`, `application/zip`, `application/cbor`, `application/octet-stream` and
  `image/png` binary payloads
- `text/plain`, `text/csv`, `text/html` and `text/markdown` text payloads
- `application/xml` alongside JSON on the same operation, as a request body as well as a
  response, plus `text/xml` and a vendor `+xml` type
- `application/yaml` and `application/vnd.api+json`
- `image/*`, a media type range, and `*/*` with an empty schema that constrains nothing
- Seven request media types on one operation at `POST /switch/messages`, and thirteen at
  `POST /diagnostics/payload`
- A body reused through `$ref` from `components.requestBodies`, whose examples are in turn
  `$ref`s into `components.examples`, including one that uses `externalValue`
- An optional body on `PATCH /diagnostics/payload`, with `required: false` spelled out

## XML

`POST /cards/{cardId}/authorizations` takes XML as its canonical request body, and its schema uses
every `nodeType` the XML object defines:

| `nodeType` | Where | On the wire |
| --- | --- | --- |
| `attribute` | `messageId`, `sequence`, `test` | `<sw:authorization messageId="..." sequence="4471">` |
| `element` | `cardId`, `capturedAt` | `<cardId>...</cardId>` |
| `text` | `XmlMoney.value` | `<amount currency="GBP">42.50</amount>` |
| `cdata` | `terminalNote` | `<terminalNote><![CDATA[Tap & go]]></terminalNote>` |
| `none` | `riskFlags` | `<riskFlag>` repeated with no wrapper |

Namespaces and prefixes appear on the root element and on a single child, `merchant/sw:country`.
`PUT /reference/tariffs` puts a collection at the root instead: an unwrapped array whose items are
discriminated by a `kind` attribute, so each `tariff` element is one of three shapes.

## JSON Schema

`oneOf`, `anyOf`, `allOf` and `not`; `if` / `then` / `else`; `const` and `enum`;
`dependentRequired`; `patternProperties`, `propertyNames`, `minProperties`, `maxProperties`,
`additionalProperties: false`; `prefixItems`, `contains`, `minContains`, `maxContains`,
`uniqueItems`; `unevaluatedProperties`; `contentMediaType` and `contentEncoding`; `readOnly` and
`writeOnly`; nullable types via `type: [string, 'null']`; a recursive `$ref` for the category
tree; and `$defs` for the query filter grammar.

<Tip>
  Read `TransferRequest` first. Which creditor identifiers are required depends on the payment
  rail, and it says so with `if` / `then` / `else` rather than three near-identical schemas.
</Tip>
