The pages below are generated from `openapi-3.1.yaml`. Each one carries a playground, but no
request reaches a real service.

## Base URL

```text
https://sandbox.api.meridian.example.com/v2
```

Production is regional, and the `tenant` server variable selects the deployment: `eu`, `uk` or
`us`.

## Conventions

| Header | When you send it | What it does |
| --- | --- | --- |
| `X-Request-Id` | Every request | A correlation id you generate. The API echoes it back, and support asks for it. |
| `Idempotency-Key` | Every write | Replaying a key within 24 hours returns the original outcome instead of a second write. |
| `If-Match` | Patches | Send the `ETag` you read earlier. A stale value is refused with `412`. |
| `If-None-Match` | Reads | Send the `ETag` you read earlier to get `304` instead of a body. |

## Pagination

Collections are cursor-paginated. Read `nextCursor` from the body, or follow the `next` relation
in the `Link` header. Do not build cursors yourself.

The `page` parameter still exists on `GET /accounts`, but it is deprecated and ignored whenever
`cursor` is present.

## Errors

Every error is RFC 9457 problem details, served as `application/problem+json`. Validation
failures add an `errors` array that points at each offending field with a JSON Pointer.

## Worth a look

- `GET /accounts/{accountId}` answers `304` when your `ETag` still matches.
- `PATCH /accounts/{accountId}` accepts both merge patch and JSON Patch on the same operation.
- `GET /accounts/{accountId}/transactions/export` streams JSON Lines or CSV.
- `POST /documents` declares a content type and headers for each multipart part.
- `GET /cards/{cardId}` serves the same resource as JSON and as XML.
- `GET /branches/{branchId}/atms/{coords}` uses the two path-only serialization styles,
  `label` and `matrix`.
