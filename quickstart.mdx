## Prerequisites

Before you begin, you need:

- A sandbox client id and secret from the developer portal.
- A tool that can send HTTP requests, such as `curl`.

## Get started

<Steps>
  <Step title="Pick an environment">
    Use the sandbox while you build. It is seeded with data, and money never moves.

    ```text
    https://sandbox.api.meridian.example.com/v2
    ```

    Production is regional. The `tenant` server variable selects the deployment: `eu`, `uk` or
    `us`.
  </Step>

  <Step title="Get an access token">
    Back-office integrations use the client credentials flow. When you act for a customer, use
    the authorization code flow instead.

    ```bash
    curl -X POST https://auth.meridian.example.com/oauth2/token \
      -u "$CLIENT_ID:$CLIENT_SECRET" \
      -d grant_type=client_credentials \
      -d "scope=accounts:read transactions:read"
    ```
  </Step>

  <Step title="Read an account">
    Send a correlation id on every request. The API echoes it back on the response.

    ```bash
    curl https://sandbox.api.meridian.example.com/v2/accounts \
      -H "Authorization: Bearer $ACCESS_TOKEN" \
      -H "X-Request-Id: $(uuidgen)"
    ```
  </Step>

  <Step title="Move money">
    Writes need an idempotency key. If you replay the same key within 24 hours, you get the
    original outcome back instead of a second payment.

    ```bash
    curl -X POST "https://sandbox.api.meridian.example.com/v2/accounts/$ACCOUNT_ID/transactions" \
      -H "Authorization: Bearer $ACCESS_TOKEN" \
      -H "Idempotency-Key: $(uuidgen)" \
      -H "Content-Type: application/json" \
      -d '{
            "rail": "sepa",
            "amount": { "amount": "120.00", "currency": "EUR" },
            "creditor": { "name": "Olha Kovalchuk", "iban": "NL91MERI0417164300" },
            "reference": "Invoice 2026-114"
          }'
    ```

    <Warning>
      This operation also needs a detached HTTP message signature (RFC 9421). A valid token on
      its own is refused.
    </Warning>
  </Step>
</Steps>

## Handle errors

Every error is RFC 9457 problem details, served as `application/problem+json`. Validation
failures add an `errors` array that points at the offending fields with a JSON Pointer.

```json
{
  "type": "https://developers.meridian.example.com/problems/validation",
  "title": "Request body failed validation",
  "status": 422,
  "detail": "2 fields are invalid.",
  "instance": "/accounts",
  "errors": [
    {
      "pointer": "/holder/dateOfBirth",
      "code": "min_age",
      "detail": "The account holder must be at least 18 years old."
    }
  ]
}
```
